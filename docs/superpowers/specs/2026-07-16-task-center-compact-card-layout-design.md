# 任务中心紧凑卡片与四象限滚动设计

**日期：** 2026-07-16  
**状态：** 用户已选择视觉方案 3，等待书面规格复核  
**关联规格：** `2026-07-15-task-center-visual-import-redesign-v2.md`

## 1. 背景与目标

真实 Obsidian 使用中暴露了三个相互关联的问题：

1. “导入旧任务”是低频操作，却位于主操作“+ 新任务”之前，且名称强调了实现来源而不是用户目标。
2. 任务卡虽然显示“待办、进行中、暂停、已完成”，但状态标签视觉差异弱，用户不能快速扫视当前执行状态。
3. 单个象限任务增多时，CSS Grid 行高会被内容撑开，同一行的空象限同步拉高，并把下方两个象限推到屏幕之外。现有任务卡的信息和常驻按钮也让每条任务占用过多高度。

本轮设计不改变 Markdown 格式、任务状态机、四象限规则、筛选逻辑、任务/日历联动或删除入口，只优化任务中心的操作层级、状态表达、任务卡密度和象限滚动行为。

## 2. 已选择的设计方向

用户选择视觉方案 3“紧凑卡片、渐进展示”。它保留当前 Obsidian 原生工作台风格，不把任务中心改造成表格，也不重新设计导航和筛选。

核心原则：

- 四个象限在宽屏下始终保持稳定的 `2 × 2` 布局。
- 每个象限具有一致的最大高度；标题固定，任务区域独立纵向滚动。
- 任务卡默认只展示决策和执行所需的信息，低频属性和操作通过编辑弹窗或菜单查看。
- 状态与四象限颜色是两套不同语义：象限颜色表达重要性/紧急性，状态颜色表达执行阶段。
- 所有颜色、表面、边框、文字和焦点状态继续基于 Obsidian CSS 变量，并跟随明暗主题。

## 3. 顶部操作顺序与命名

右上操作顺序固定为：

1. `任务 / 日历` 分段切换。
2. `+ 新任务`，主按钮，继续使用 Obsidian 强调色。
3. `导入任务`，次级按钮。

界面与命令面板中的用户可见名称统一从“导入旧任务”改为“导入任务”。内部 action、命令 ID、迁移服务和数据兼容逻辑保持不变，避免破坏已有调用或配置。

## 4. 四象限布局与滚动

### 4.1 宽屏

- 象限继续使用两列网格。
- 网格项顶部对齐，单个象限的内容不得决定整行的无限高度。
- 每个象限由固定标题区和可滚动任务区组成。
- 四个象限采用相同的最大高度；任务不足时允许留白，任务过多时仅任务区滚动。
- 象限标题、计数和顶部语义色条始终可见，不随内部任务列表滚走。
- 滚动条使用 Obsidian/浏览器原生滚动行为，保持窄且低噪声，不引入横向滚动。

建议实现值以真实 Obsidian 视口验证为准，初始目标为单个象限高度约 `min(360px, 36vh)`，并设置合理最小高度，保证常见桌面窗口能同时看到四个象限。

### 4.2 窄屏

- 继续沿用现有断点降级为单列。
- 单列下象限仍保留最大高度和内部滚动，避免任一象限吞掉整个页面。
- 不得出现任务卡、元数据或按钮的横向滚动。

### 4.3 未分类收件箱

未分类收件箱不属于四象限网格，继续位于网格上方。其内容较多时也应采用同一紧凑任务卡表达，但本轮不强制与四个象限使用相同固定高度。

## 5. 紧凑任务卡

### 5.1 默认结构

任务卡目标高度约 `72–84px`，内容最多形成三个紧凑层级：

1. **主信息行**：状态色条、任务标题、状态标签、可选截止风险标签、右侧更多菜单。
2. **详情摘要行**：显示一行详情；超长内容使用省略号，不增加卡片高度。无详情时不保留空白占位。
3. **核心元数据行**：优先显示项目和截止日期；没有对应字段时不显示分隔符或空标签。

标题保持任务卡内最强层级。来源文档、完整标签、完整计划日期和其他低频元数据不在默认卡片常驻展示，可在编辑弹窗中查看。

### 5.2 操作收敛

- 不再在每张卡片底部常驻“开始、暂停、完成”等按钮。
- 卡片右上角保留现有更多菜单；编辑和状态变更操作从该入口或卡片交互进入。
- 点击卡片继续打开现有编辑弹窗，不增加新的详情页。
- 删除入口继续位于编辑弹窗底部，不移动到任务卡菜单，遵循已确认的低频危险操作设计。

### 5.3 子任务与风险

- 有子任务时，进度以紧凑文字或徽标呈现，例如 `2/4`，不得生成额外大块区域。
- 截止风险只在需要时显示，例如“今天到期、临近截止、已逾期”。
- 截止风险使用危险/警告语义色，但不得替代或覆盖任务状态标签。

## 6. 状态视觉系统

状态必须同时使用文字和颜色，不能只依赖颜色：

| 状态 | 视觉语义 | 卡片表现 |
| --- | --- | --- |
| 待办 | 中性、尚未开始 | 冷灰色标签与左侧色条 |
| 进行中 | 当前正在执行 | Obsidian 强调紫/蓝标签与左侧色条 |
| 暂停 | 临时中断、等待恢复 | 琥珀/橙色标签与左侧色条 |
| 已完成 | 已结束 | 绿色标签与左侧色条，标题降低强调度，可配合完成图标或轻量删除线 |

实现约束：

- 复用任务卡已经输出的状态 class，不用状态文字做 CSS 选择器。
- 标签至少区分前景色、浅背景和边框；明暗主题中都必须达到清晰可读。
- 不使用整张卡片的大面积状态底色，避免与四象限语义色冲突。
- 待办和已完成即使在灰度环境下，也应通过文字、明暗和完成装饰保持可辨识。

## 7. 组件与实现边界

- `WorkspaceHeader`：调整创建/导入按钮顺序和可见文案。
- 插件命令注册：同步更新导入命令的可见名称，保留命令 ID。
- `TaskWorkspaceView`：为象限标题与任务列表建立明确容器边界，使列表可以独立滚动。
- `TaskCard`：重排主信息、摘要和元数据，复用现有状态 class，收敛常驻操作。
- `styles.css`：增加状态 token 映射、紧凑卡片、固定象限高度、内部滚动和窄屏退化样式。
- 任务仓库、Markdown 解析/写入、筛选和状态变更服务不在本轮修改范围。

## 8. 可访问性与交互

- 所有状态标签保留可见中文文字。
- 更多菜单、卡片和可交互状态保留键盘焦点样式。
- 可滚动象限必须可通过鼠标滚轮、触控板和键盘访问，滚动焦点不能导致整个页面意外跳动。
- 截断详情和隐藏元数据不会丢失数据；完整内容始终可从编辑弹窗读取。
- 明暗主题均不得出现硬编码黑色文字、白色背景或低对比状态标签。

## 9. 测试与验收

自动化测试至少覆盖：

1. 顶部按钮顺序为“+ 新任务”后接“导入任务”，创建按钮仍为唯一主操作。
2. 命令面板显示“导入任务”，原命令 ID 保持不变。
3. 任务卡为每种状态输出稳定、独立的状态 class 与中文标签。
4. 任务卡不再渲染常驻状态操作按钮，更多菜单和编辑入口仍可用。
5. 象限包含独立任务列表容器，CSS 合约包含最大高度、纵向滚动、固定标题和无横向溢出。
6. 长标题、长详情、长项目名、无详情、无项目、无截止日期和子任务进度均不破坏布局。
7. 现有创建、编辑、删除、筛选、任务/日历切换和导入功能回归测试继续通过。

真实 Obsidian 验收至少覆盖：

- 明色和暗色主题下四种状态均清晰可辨。
- 一个象限至少放入 8–12 条任务，确认只有该象限内部滚动，其他三个象限仍保持可见。
- 四个象限分别测试空状态、单任务和多任务组合。
- 宽屏 `2 × 2` 与窄屏单列均无横向滚动或遮挡。
- `+ 新任务`、`导入任务`、卡片编辑、状态切换和更多菜单均可正常操作。

## 10. 非目标

- 不改变标准任务 Markdown 格式或导入迁移格式。
- 不新增任务详情页、看板视图、批量操作或自定义状态颜色设置。
- 不改变四象限分类规则和“执行前必须分类”的约束。
- 不重新设计搜索和筛选控件。
- 不改变日历视觉结构，只保证共享任务卡/状态表达不会破坏日历联动。

## 11. 完成标准

本轮完成必须同时满足：

1. 三个用户问题均在真实 Obsidian 中可见地解决。
2. 实现与用户选择的视觉方案 3 保持一致，而不是只修改几个 CSS 数值。
3. 全量测试、覆盖率、lint 和生产构建通过。
4. 构建产物安装到本地 Vault 前先备份现有插件，并校验安装产物哈希。
5. 在真实 Vault 中完成不写入或使用专用测试任务的交互冒烟验证，不修改用户现有任务内容。
